OSP v0.6 "Connect" — Requirements

Remote LLM providers · Discovery services · MCP server surface · Testability. Written before implementation, per project rule. Traceability: every requirement cites the test that proves it.

Scope & Assumptions

  • In scope: (1) pluggable D3 providers — local SLM, remote OpenAI-compatible endpoint, and an adapter for a future ../LLMprovider service; (2) a discovery service (lease-based node directory with node classes); (3) an MCP server exposing OSP operations; (4) an executable test suite proving the convergence and firewall guarantees of v0.4/v0.5.
  • Assumption (verified 2026-09-17): ../LLMprovider, ../harnessdroid, ../whatsapp do not exist on disk yet. All three are integrated against documented contracts, flagged as such, not against real code.
  • Environment: Python 3.13, Node 20, no mcp package installed ⇒ the MVP server is stdlib-only JSON-RPC 2.0 over stdio (MCP wire format), swappable for the official SDK later (REQ-NF-01).
  • Preserved invariants: all v0.4 convergence rules (gas monotonicity, path-vector loops, mapping contraction, quorum + provenance diversity) and the three firewall layers. Remote providers must not weaken them — see REQ-F-02.

Functional Requirements

REQ-F-01 MUST — Pluggable D3 provider binding

The D3 rung (generation) SHALL be an interface with three implementations: local SLM stub, remote OpenAI-compatible endpoint (OSP_PROVIDER_URL/OSP_PROVIDER_MODEL/OSP_PROVIDER_API_KEY), and a file-contract adapter for ../LLMprovider (reads ../LLMprovider/osp_endpoint.json when present). Switching providers is a configuration change only; protocol tests MUST pass unchanged under any provider.

AC: test_provider_swap_equality — the same query suite runs green with EchoGrounded and with a scripted remote stub.

REQ-F-02 MUST — Providers are untrusted generators

A remote provider receives only: the query, the retrieved chunks (with hashes), and a grounding instruction. Its output is data, never authority: it goes through the full firewall (L2 entailment, quorum tiers, reputation) exactly like a local answer. A provider that ignores its evidence MUST produce a rejected outcome, never an accepted one.

AC: test_confabulating_provider_rejected — confabulating provider wins the auction ⇒ outcome REJECTED, reputation decays.

REQ-F-03 MUST — Node classes in discovery

Nodes declare a class: N1 thin (D0–D1 only, no generation), N2 full (local D3), N3 provider-backed (remote D3). Discovery records the class; origin nodes route RESOLVE-stage work only to nodes whose class can serve it. An N1 node participates in routing and pre-bidding but MUST abstain from generation.

AC: test_thin_node_delegates — query routed through an N1 node resolves via an N3 node; test_budget_exhausted_abstains — N3 with empty budget abstains from RESOLVE.

REQ-F-04 MUST — Cost accounting for remote D3

Every D3 invocation charges the node budget (generations, and for remote providers: tokens + estimated cost). Budget exhaustion degrades the node to D0/D1-only participation (it still routes and pre-bids). Daily caps are configurable.

AC: test_budget_exhausted_abstains; osp_status reports budget state.

REQ-F-05 MUST — Discovery service

A lease-based directory SHALL provide: register / renew / expire / lookup. A record carries: node_id, key bundle (signing key + prekey), endpoints, transports, node class, topic codebook, lease TTL. Expired leases are invisible to lookup. Bootstrap order: configured seeds → mDNS (LAN, future) → directory (WAN). The MVP ships the in-memory directory and its interface.

AC: test_discovery_lease_expiry, test_discovery_topk_lookup.

REQ-F-06 MUST — MCP server surface

An MCP stdio server (JSON-RPC 2.0, newline-delimited) SHALL expose: osp_query(text, tier), osp_discover(topic, top_k), osp_advertise(topic, klass), osp_status(), osp_explain(query_id). The dispatcher MUST be callable in-process for testing without spawning a process. Tool outputs include the outcome mode and an audit trace.

AC: test_mcp_dispatch_smoke — initialize → tools/list → tools/call round-trip in-process.

REQ-F-07 MUST — Semantic preservation

All five convergence modes and their triggers are preserved in provider mode: RESOLVED, MISMATCH, GAS_EXHAUSTED, LOOP_DETECTED, NO_QUORUM — plus REJECTED (firewall). Worst-case termination stays bounded at G + C + R rounds.

AC: test_resolved_t1, test_mismatch_contraction, test_gas_exhausted, test_loop_detected, test_no_quorum, test_replay_rejected.

REQ-F-08 SHOULD — Pluggable D2 verifier

The entailment check is an interface. The MVP ships a deterministic lexical verifier (clearly marked dev-grade); a real NLI cross-encoder or provider-based checker plugs in behind the same interface. Outcomes MUST NOT depend on which verifier implementation is installed, only on groundedness results.

AC: interface exists; test_confabulating_provider_rejected passes through it.

Non-Functional Requirements

REQ-NF-01 MUST — Zero third-party runtime dependencies (MVP)

The server and tests run on Python 3.13 stdlib only. The official MCP SDK migration path is documented; the transport layer is isolated behind one module so the swap is mechanical.

AC: test suite runs on a clean venv with no pip installs.

REQ-NF-02 MUST — Privacy tiering for remote providers

Tier T2 (sensitive) queries MUST NOT be sent to remote providers unless explicitly allowed in configuration (allow_remote_t2: false by default). Providers receive evidence chunks, never the local RAG itself.

AC: test_t2_never_remote_by_default.

REQ-NF-03 MUST — Deterministic, offline tests

No test makes a network call. Stub providers are deterministic. Randomness only via fixed seeds.

AC: CI-safe run on airplane-mode machine.

REQ-NF-04 SHOULD — Auditability

Every query produces a trace (packets, verdicts, costs) retrievable via osp_explain — a protocol that rejects answers must be able to show why.

AC: test_explain_trace_complete.

REQ-NF-05 SHOULD — Latency budget

Remote-provider path adds ≤ 5 s p50 over the local path (target, measured later on real hardware — all §7 numbers in v0.5 remain modeled until then).

AC: benchmark harness exists; numbers reported, not asserted in CI.

Security Requirements

REQ-S-01 MUST — Honest cryptography posture

The MVP signer is HMAC-SHA256 over canonical JSON and is labeled DEV-SIGNER everywhere it appears. Production SHALL use Ed25519 (RFC 8032) via COSE/JWS as specified in v0.4. Deploying with the dev signer is a spec violation, not a configuration.

AC: signer interface isolated; label asserted in code and README.

REQ-S-02 MUST — TOFU key pinning in discovery

Directory registration pins the first key bundle seen per node_id; a changed bundle is rejected unless an explicit re-pinning action is taken. Discovery announcements are subject to the same replay protection (jti cache) as protocol packets.

AC: test_tofu_pinning, test_discovery_replay_rejected.

REQ-S-03 MUST — Provider prompt-injection containment

Evidence chunks are quoted data inside the grounding envelope; directive-looking text inside chunks is neutralized by the envelope, and provider output is never executed — only verified. The MVP ships a naive directive-stripper and marks it as such.

AC: test_injection_neutralized — a chunk containing an instruction to ignore context still yields a grounded or rejected answer.

Explicit Non-Goals (v0.6)

  • Real WhatsApp / BLE transports (interfaces only; see v0.5 §4).
  • mDNS/LAN bootstrap (directory interface anticipates it; implementation later).
  • Ed25519 (pending a crypto dependency decision — the only justified deviation from REQ-NF-01 when it happens).
  • Multi-server interop over real transports (in-memory hub first).
